# DIYASI SEO 分批提交与观察 SOP

上线与 Google 收录是两件事。本轮页面可以统一部署，但人工请求收录按以下批次执行。sitemap 会公开全部合格规范页，搜索引擎仍可自行发现它们；本 SOP 控制的是主动提交节奏，并非保证 Google 分批抓取。

## 首批：6 个 URL

- https://www.yiwudiyasidress.com
- https://www.yiwudiyasidress.com/manufacturers
- https://www.yiwudiyasidress.com/manufacturers/private-label-underwear-manufacturer
- https://www.yiwudiyasidress.com/manufacturers/low-moq-underwear-manufacturer
- https://www.yiwudiyasidress.com/manufacturers/custom-underwear-manufacturer
- https://www.yiwudiyasidress.com/manufacturers/seamless-underwear-manufacturer

在正确的 Search Console 属性中提交 sitemap，并用 URL 检查核验这 6 页。保存提交日期、Google 选择的 canonical、实时测试和索引结果。没有实际操作证据时，记录“未提交”，不能把部署时间当提交时间。

## 观察与后续批次

首批提交后观察 7–14 天。检查“已抓取但尚未编入索引”的具体页面、是否出现查询曝光、Google canonical 是否正确及抓取是否成功。仅在该批无持续增加的异常且有正常发现/收录信号时继续；曝光不足可能是需求量低，应区分样本不足和技术故障，不机械要求所有页面立即有曝光。

后续每批最多 10 个新 URL，每批至少间隔 7 天：剩余 P1 → P2 → 六篇指南及指南索引 → 西语 → 法语 → 德语 → 意大利语。按当前 51 个新路由加首页计算，首批 6 个后还需约 5 批；遇到异常延长到 6–8 批或更久。日期以首批真实提交日为起点，不预填未来执行记录。

## 异常处理

如果某批“已抓取但尚未编入索引”持续增长，暂停主动扩量，检查该批真实 HTML、canonical、内部发现路径、内容相似度和证据增量。检查状态码、站点日志与 Google 实时测试，不能仅根据审计工具的分数判断。模板修复并复检后再申请重抓；不要反复提交相同 URL 代替修复。

保留后台、付款、结账和参数页的合理排除。重定向旧 URL 不回填 sitemap。对有价值的规范页修复误伤，不能把“未收录”全部解释为 noindex。

## 效果记录

每次记录同一属性、日期范围、国家、设备和搜索类型。对比完整 28 天点击、曝光、CTR、查询与页面，以及真实有效询盘。按钮点击不等于有效询盘。低量 B2B 查询可能需要较长观察；6–12 个月只是规划窗口，不是排名或流量保证。附件中的搜索量、难度与增长百分比为用户提供的研究输入，本轮没有重新获取第三方数据验证。

人工后续：抽取首页、采购页、产品页共 3 页执行 Google Rich Results Test；普通 Service/FAQ 标记合法不代表可获得富结果。商品不提供 Offer 或评分，因此不宣称具备 Product 富结果资格。工厂实拍、真实报价/认证及合规引用建设需按真实资料补充，不购买操纵排名链接。
